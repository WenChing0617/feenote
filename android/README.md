# 电费记账本 · 安卓版

302 室宿舍电费记账工具的手机版。数据全部存在手机本地 SQLite 数据库里，**不上传、不经过任何服务器、不需要账号**。

和电脑上的桌面版可以双向同步：**同一个 WiFi 下点一下就完成**（局域网直连），不想连网也可以用「导出 / 导入账本 JSON」文件互传。

> v1.2 起新增「电脑同步」，v1.3 把它拆成「同步到手机 / 同步到电脑」两个方向并加了疑似重复提醒，
> **v1.4 起应用不再自带任何数据**（装完是空账本，由首次引导问你自己填）。
> 应用只在这一个功能里发起网络请求，
> 目标就是你自己那台电脑，且必须带 4 位配对码；数据不出局域网。
> 主要权限只有 `INTERNET` 和 `ACCESS_NETWORK_STATE`（后者仅用来判断在不在 WiFi 上）。

## 一、怎么出 APK

### 方式一：Android Studio（推荐，点几下就行）

1. 打开 Android Studio → 菜单 `File` → `Open`
2. 选中安卓工程目录（选到含 `settings.gradle.kts` 的这一层）
3. 首次打开会自动开始 Sync，需要联网下载 Gradle 和依赖，**首次几分钟到十几分钟都正常**
4. Sync 完成后：菜单 `Build` → `Build Bundle(s) / APK(s)` → `Build APK(s)`
5. 右下角弹出提示点 `locate`，产物在：

```
app\build\outputs\apk\debug\app-debug.apk
```

### 方式二：命令行

```powershell
cd "<安卓工程目录>"                            # 含 settings.gradle.kts 的那一层
$env:JAVA_HOME = "D:\Android Studio\jbr"      # 指向 Studio 自带的 JDK，按你的安装位置改
.\gradlew.bat assembleDebug
```

> `JAVA_HOME` 这一句是必须的。Gradle 自己不认 Android Studio 的设置，不加会报「找不到 Java」。
> 如果直接在 Android Studio 的 Terminal 里敲 `.\gradlew.bat assembleDebug`，一般已经带好了 JDK，可以省掉。

产物路径同上。

## 二、装到手机

**不用数据线**（最简单）：
1. 把 `app-debug.apk` 传到手机（微信文件传输助手 / QQ / 网盘都行）
2. 手机上用文件管理器点开它
3. 首次会提示「允许安装未知应用」，同意即可

**用数据线**：
1. 手机：`设置` → `关于手机` → 连点「版本号」7 次，开启开发者模式
2. `设置` → `系统` → `开发者选项` → 打开 **USB 调试**
3. 数据线连电脑，然后：

```powershell
cd "<安卓工程目录>"
%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe install -r app\build\outputs\apk\debug\app-debug.apk
```

## 三、功能

| 页面 | 能干什么 |
|---|---|
| **明细** | 按日期倒序看所有充值记录，同一天的会归到一组并显示当天合计；顶部是累计总额与大字余额；点右下角 `+` 记一笔，点任意一条可以改或删 |
| **统计** | 每人累计金额、充值笔数、占总金额比例（带彩色进度条） |
| **设置** | **首次设置引导**、改房间号、成员管理（增/改名/删）、**撤销 / 恢复**、**电脑同步（局域网）**、**查重**、导出 / 导入账本 JSON、导出 TXT 与 CSV、复制报告到剪贴板、回收站 |

界面配色是清透天蓝系（`#3A87F0`），应用图标是渐变蓝底 + 白色闪电，跟桌面版同一套色。

**装完是空账本**，第一次打开会引导你填房间号和室友（见「四、数据存在哪」一节）。

### 记账时的细节

- **谁充的**：从成员里点选；编号是你**添加成员的顺序**（1、2、3…），可在设置里调整
- **金额**：只允许数字和小数点；下面有一排**快捷金额**（¥50 / ¥100 / ¥200 / ¥300 / ¥500），点一下直接填进去，不用每次敲
- **日期**：点一下弹出**月视图日历**，默认选中今天
- **支付方式**：默认「校园卡」，可切微信 / 支付宝 / 现金
- **备注**：可留空

> 手机端**没有**「期初首笔」开关。那是桌面版的历史口径（那笔算进总额但不计笔数），
> 手机只做日常记账，用不上。从电脑同步过来的期初记录，编辑时原标记会原样保留，不会被抹掉。

### 撤销 / 恢复

每做一次改动（记一笔、改一笔、删除、恢复、清空回收站、成员增删改、导入、同步），
底下都会弹一条提示，点「**撤销**」就能一步退回去；撤销之后再点「**恢复**」又能回来。

- 靠的是**整份账本的快照**，不是逐条反向操作 —— 所以每种操作都天然可撤销，不会漏
- 最多记 **30 步**，超了丢最老的
- 做了新动作之后，「恢复」就清空了（和所有编辑器的行为一致）
- 提示条只停几秒；错过的话到 **设置 → 操作历史** 里随时能撤销/恢复，那里会写明这一步是什么

### 删除是软删除

删掉的记录会进**回收站**（设置 → 回收站），可以单条恢复、单条彻底删除，或一键清空。删成员也是同理：TA 的记录会一起进回收站。

## 四、数据存在哪

- 位置：手机应用私有目录 `databases/feenote.db`（SQLite）
- **卸载应用才会清除**，平时升级安装不影响数据
- 已开启系统云备份（换手机时若登录同一账号，数据可以跟着走）
- 想手动备份或给别人看，用「设置 → 导出 CSV / TXT」

### 首次打开是空白的（应用不带任何数据）

这个版本**不带任何预置账目、也不带任何预置成员**。装好打开，账本是空的 ——
不会看到别人的房间号和室友名字，谁装都是自己的。

**首次使用引导**会问两件事，一分钟就能填完：

| 项 | 说明 |
|---|---|
| 房间号 | 例如 `302`、`B栋415`。留空也行，只是标题不显示房间 |
| 宿舍成员 | 谁交电费就填谁，**编号按添加顺序排（1、2、3…）** |

- 点「以后再说」也能跳过，之后随时到 **设置 → 首次设置引导** 重新打开
- 一个人都还没加的时候，明细页会提示「还没有成员」，点一下就能补
- 想加人 / 改人 / 删人，走 **设置 → 成员管理**（删人会把它名下的记录一并移入回收站，可恢复）

> 早期的版本（v1.3 及以前）自带过一份 5 人 40 条的示例账目。
> **v1.4 起已彻底移除**，从旧版升级上来的用户数据不受影响，只是新装的是干净的空账本。

## 四.5、和桌面版「同一份账本」

手机和电脑用的是**同一套 JSON 格式**，靠每条记录上的 12 位 `uid` 认人，
所以两边的数据可以互相同步、互相导入，不会重复记账。详见下一节。

## 五、和电脑上的桌面版互通

有两条路，任选：

| 方式 | 适合 | 需要 |
|---|---|---|
| **电脑同步（局域网）** | 平时最顺手，点一下就对完账 | 两台连同一个 WiFi；电脑上桌面版开着 |
| **文件互传（JSON）** | 不在同一个网、或者想留个备份 | 一个能传文件的途径（微信 / QQ / 数据线） |

两端**共用同一套 JSON 格式**，靠 12 位 uid 去重，所以两种方式可以混着用，不会重复记账。

---

### 5.1 电脑同步（局域网直连）

**电脑这边（一次性）**

1. 打开桌面版，点顶栏 **「手机同步」**
2. 点 **「启动服务」**
3. 面板上会显示两样东西，记下来：
   - **服务地址**，形如 `http://192.168.1.5:8686`
   - **配对码**，4 位数字，每次启动随机（可以点「换个配对码」换一个）

> 第一次启动时 Windows 可能弹防火墙提示，**要选「允许访问」**（专用网络打勾），否则手机会连不上。

**手机这边（也是一次性）**

1. `设置` → **电脑同步（局域网）**
2. 填电脑地址（`192.168.1.5` 就行，`http://` 和端口可以不带）、端口、配对码
3. 先点 **「测试连接」** —— 连上了会告诉你电脑上有多少条记录，确认地址没填错
4. 再按需要点 **「同步到手机」** 或 **「同步到电脑」**

地址和配对码会记住，以后再同步打开面板点一下就行。

**两个方向是分开的，不会一次全同步**

| 按钮 | 方向 | 干什么 |
|---|---|---|
| **同步到手机** | 电脑 → 手机 | 把电脑上有、手机上没有的取回来。**只读电脑**，不改动电脑上的账 |
| **同步到电脑** | 手机 → 电脑 | 把手机上有、电脑上没有的推过去。电脑按 uid 合并，不覆盖它原有的记录 |

两个方向都是**删除优先** —— 一端删掉的记录，另一端会跟着进回收站（不是销毁，还能恢复）。

**同步前会先「预演」一遍，发现疑似重复会拦住你**

uid 只能保证「同一条不会被同步两次」，拦不住**两边各自手输了同一笔账** ——
那种情况两边各拿一个 uid，直接合就会变成两份。

所以两个方向在动手之前都会先算一遍：

- 找出「**同一个人 + 同一天 + 同一个金额**」但 uid 不同的记录
- 如果发现了，弹框把这些列出来（连带两边的备注，方便辨认），问你怎么办：
  - **「跳过这些，同步其它的」**（推荐）—— 那几条不推也不取，两边不会变成两份
  - **「全都同步」** —— 你确认它们确实是两笔不同的账，照常合
  - **「取消」**
- 同步结果里也会写明这一趟跳过了几条

**事后想复核**：`设置` → **查重**，会列出手机本地所有「同人 + 同日期 + 同金额」出现两次以上的记录，
确认是同一笔就点「删这条」（进回收站，还能恢复）。

> 从文件导入账本时也一样会检测：如果文件里有和手机疑似同一笔的，弹窗里会先提醒你。

**连不上怎么办**

| 提示 | 多半是 |
|---|---|
| 连不上电脑 | 电脑上没点「启动服务」/ 两台不在同一个 WiFi / 防火墙拦了 |
| 电脑没反应（超时） | 不在同一个 WiFi，或者电脑休眠了 |
| 配对码不对 | 电脑上显示的 4 位数要跟手机里填的一模一样 |
| 这个地址上没有同步服务 | 端口填错了（默认 8686） |
| 手机上填 127.0.0.1 指的是手机自己 | 要填电脑在 WiFi 里的地址，不是 127.0.0.1 |

**安全上说明白**

- 服务只在电脑上手动开了才存在，关掉窗口就断
- 请求必须带对 4 位配对码，同一 WiFi 下别人扫到端口也读不到、更写不进
- 数据只在手机和电脑之间跑，不经过任何外部服务器
- 应用除这个功能外不发任何请求，也没有埋点

### 5.2 文件互传（不用局域网时）

**手机 → 电脑**

1. 手机上：`设置` → `导出账本 JSON`
2. 把文件传到电脑（微信 / QQ / 数据线都行）
3. 电脑上：桌面版 → `导入账本` → 选那个文件 → 弹窗里选 **合并**

**电脑 → 手机**

1. 电脑上：桌面版 → `导出账本备份`，得到一个 `.json`
2. 传到手机
3. 手机上：`设置` → `导入账本 JSON` → 选文件 → 选 **合并**

| 方式 | 行为 | 什么时候用 |
|---|---|---|
| **合并**（推荐） | 两边记录都保留，同一条只留一份，回收站也一并同步 | 两边都记过账 |
| **覆盖** | 用文件内容整个替换手机账本，手机上多出来的记录会消失 | 确定以某一端为准 |

### 5.3 去重是靠什么做到的

每条记录都带一个 **12 位十六进制的 uid**（例如 `ce3f1890bccc`）。

uid 是**跨设备的唯一身份**：手机本地那条自增主键出了这台机器就不认了，所以两端一律用 uid 认人。
数据库里给它建了唯一索引，导入时按它去重 —— 同一笔账在两端来回导多少遍，也只会留一份。

> 手机从**空账本**开始，uid 由应用生成（12 位随机十六进制）。
> 从电脑导入时，电脑那份文件里的 `id` 会被原样当作 uid 收下，所以之后再同步不会重复。

**删除也会传播**：一端移进回收站的记录，另一端合并时会跟着移进回收站，不会被别的文件反复「复活」。
（桌面版 v1.5 已修正原先「删除不传播」的行为，两端现在完全一致。）

> uid 只能拦住「同一条被同步两次」。要是**两边各自手输**了同一笔，两边会各拿一个 uid，
> 单靠 uid 认不出来。所以 v1.3 又加了一层**弱去重**：
> 用「**谁 + 哪天 + 多少钱**」组成的弱键（金额换算成「分」再比，避开浮点误差）
> 来发现这种「内容一样、身份不同」的重复，在同步前弹框让你决定，事后也能在「查重」里复核。

> 两条设计原则，改代码前值得知道：
> 1. **纯逻辑一律不碰 SQLite** —— `SyncPlanner` / `SnapshotStack` / `Onboarding`
>    都是独立的 object 或泛型类，`Repository` 只做「查库 + 委托」。
>    这样才能在 JVM 上跑单测（`Repository` 依赖 `SQLiteDatabase`，跑不了）。
> 2. **撤销靠整份快照**，不写逐条反向操作 —— 新增任何写操作都天然可撤销，不会漏。

### 同步协议

电脑那边是个极小的 HTTP 服务（桌面版顶栏「手机同步」启动），三个接口：

| 接口 | 作用 |
|---|---|
| `GET /ping?pair=xxxx` | 探活，顺便报电脑上有多少条记录 |
| `GET /export?pair=xxxx` | 取回电脑上的整本账本（桌面版 JSON 格式） |
| `POST /import?pair=xxxx` | 把手机账本推给电脑，按 uid 去重合并 |

配对码不对一律 403。桌面版实现见 `电费记账本.py` 里的 `SyncServer`。

> 安卓端**没有**用 coroutines / OkHttp：本机 Maven Central 不通，多一个依赖就多一分拉不到的风险，
> 而一次同步只有两三个请求。就用 `Thread` + `Handler` 把结果抛回主线程。

> `check_lan_sync.py` 必须用**带 tkinter 的 Python**（它要 import 桌面版模块），
> 也就是桌面版能跑的那个 Python。脚本会把账本复制到临时目录再操作，**不碰原件**。

> ⚠️ **单元测试要求工程放在纯英文路径下。**
> 有些机器的 JVM 是 `sun.jnu.encoding=GBK`，而测试 worker 的 classpath 里一旦含中文路径就会解析失败，
> 报 `ClassNotFoundException: ...JsonCodecTest`（编译是好的，是加载阶段挂了）。
> 遇到这种机器，把工程复制到纯英文路径下再跑即可。
> **只出 APK 的话不受影响**（`assembleDebug` 不跑测试）。

### 四个环境相关的坑（已经处理好了）

1. **Gradle 下载源**：官方 `services.gradle.org` 在本机网络下不通，`gradle/wrapper/gradle-wrapper.properties` 里的 `distributionUrl` 已指向腾讯云镜像。
2. **JDK 25**：Studio 自带的 jbr 是 JDK 25，只有 Gradle 9.x 支持它，所以整套用 Gradle 9 + AGP 9。别把 Gradle 降到 8.x，会直接报错。
3. **AGP 9 内建 Kotlin**：AGP 9.0 起 Kotlin 支持已内建，**不能再声明 `org.jetbrains.kotlin.android` 插件**（三处都不能留：模块级、顶层、版本目录 `libs.versions.toml`）。同时 **Kotlin 版本必须锁到 AGP 内建的那一版**——AGP 9.2.0 对应 2.2.10，写高了（比如 2.2.20）Gradle 会把整个 Kotlin 抬上去，属于没被 AGP 验证过的组合。
4. **工程路径含中文**：AGP 默认拒绝含非 ASCII 字符的路径，`gradle.properties` 里已加 `android.overridePathCheck=true` 放开。本项目纯 Kotlin/Java、不含 NDK，放开是安全的。

### 依赖仓库（重要）

Maven Central 官方源 `repo1.maven.org` / `repo.maven.apache.org` 在本机网络下**完全不通**，
直连 GitHub 还会撞上证书链问题，首次构建就是卡在下载 `kotlin-compiler-embeddable` 这个 jar 上。

所以 `settings.gradle.kts` 里已改成**国内镜像优先**：

| 用途 | 仓库 |
|---|---|
| AndroidX / Google 系 | `google()`（dl.google.com，本机实测可达）、`maven.aliyun.com/repository/google` |
| Kotlin / Maven Central 系 | `maven.aliyun.com/repository/public`、`mirrors.cloud.tencent.com/nexus/repository/maven-public` |
| 兜底 | `mavenCentral()` |

换到网络通畅的环境也能直接用，不用改回来。
